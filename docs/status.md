## 実際に確認したこと

- Rustの解析・制約・状態制御・Git実リポジトリを使うテスト。
- TypeScriptの型検査、フロントエンドのテスト・本番ビルド、RustのClippy。
- 実際のTauri／WebView2画面から、環境調査、空白を含むパスのリポジトリ登録、検証計画、コマンド実行、履歴保存。
- 配布用実行ファイルを、開発サーバーなし・管理ツールのPATHなしで起動。
- 一時リポジトリで実際のパッケージを更新し、テスト成功と、失敗後の再実行拒否を確認。
- この環境のWSLを別々に検出し、開発用PythonとOS用Pythonを分けて取得。既存プロジェクトは調査のみで変更していない。
- npm監査の既知の問題は修正後に0件。Cargoを含むOSVの残存情報は下記を参照。

実際のGitHubへのプッシュ・PR作成・マージ、管理ツールの更新・削除、OSインストーラーの実行は、このアプリの検証のために既存環境へ実施していない。これらは確認済み計画を利用者が実行する機能として実装し、制御・入力・CI判定を検査した。

CIワークフローは追加済み。先行コミットのActionsでは検出試験のパス比較で失敗し、ローカル修正済み。今回のGitHub調査機能も含めた最新のリモートCI成功は未確認。

## 既知の制限・今後の範囲

- 実配布・実機検証の対象はWindows。macOS・LinuxネイティブUIは未検証。共通コアのCIマトリクスとOS別連携の分離は実装済み。
- すべての管理ツール・パッケージ形式を網羅しない。Yarn/Bunの自動更新、.NET/Goなどの依存更新、従来のrequirements形式の完全解析は未対応。
- カスタムnpmレジストリは公開レジストリと混同せず、照合・自動更新の対象外とする。すべての企業向けレジストリ設定を解釈する機能ではない。
- 同一メジャーであっても互換性は保証しない。Pythonの複数プラットフォーム解決など現在版を一意に特定できない場合は、自動更新候補を確定しない。
- サポート終了日の全製品横断照合、メジャー移行の自動生成、AI補助、定期実行、複数PC同期は未実装。
- 削除の証拠は登録範囲と現在の権限で取得できる情報に限定される。Python・WSL・OS・アプリ同梱ランタイムの削除、キャッシュ・作業ツリーの一括削除は実装していない。
- MCPの実接続確認と、専用MCP仮想環境の自動移行は未実装。
- 外部コマンドやインストーラーの完全なロールバックは提供しない。差分・ログを確認して復旧し、新しい計画を作成する。
- 署名、インストーラーの公開、アプリ自身の自動更新は未設定。ツール更新から独立した配布経路として、公開時に設定する。

## Cargoロックの残存アドバイザリ

全プラットフォームのロックをOSVに照合すると、TauriのLinux向けGTK経路に次が残る。

| 依存                   | 情報                                                                                                                 | 現在の扱い                                                                                                    |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| glib 0.18.5            | [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html)：VariantStrIterの不健全性。修正は0.20以降 | 現行TauriのGTK依存と互換な単純差し替えは行わない。LinuxネイティブUIを配布する前に上流対応または修正を検証する |
| proc-macro-error 1.0.4 | [RUSTSEC-2024-0370](https://rustsec.org/advisories/RUSTSEC-2024-0370.html)：保守停止の注意情報、修正版なし           | glib-macros経由のLinux向け依存。上流の移行を追う                                                              |

Windowsターゲットの `cargo tree -i ... --target x86_64-pc-windows-msvc` では、両依存とも利用経路がないことを確認した。ロックファイル全体からの検出と、配布するWindows実行ファイルの到達性は別であり、「全OS・全依存の問題がゼロ」とは報告しない。

初期のVitest系の既知の問題は修正版へ更新した。また、pnpmロックの旧12系自動取得メタデータは、必要な複数文書構造を残して整理し、11系での凍結インストールを確認した。

## ナビゲーション再編

主要画面を「概要／環境・ツール／プロジェクト／更新」、補助画面を「履歴／設定」に整理した。プロジェクトはリポジトリ単位の統合一覧とし、更新候補・静的方針・実行計画を「更新」に集約した。環境切り替えによるプロジェクト・計画の非表示を解消した。

Vitest 10件、Rust単体39件・Git連携3件、Clippy、実アプリの通し試験、GitHub模擬API試験、配布用実行ファイルの起動試験を通過。作業環境のリモート・コミット・未コミット変更の確認も検証した。リモートCIは未確認。操作の整理は [navigation.md](navigation.md) を参照。

ナビゲーション再編後の確認で、更新方針からのクローンに対象の引き継ぎと画面移動の不足が見つかったため修正した。調査コミットのチェックアウト、プロジェクト詳細への移動、元の方針への復帰、概要から計画一覧への移動をネイティブ通し試験に追加した。Windowsのクローン先引数に使用するパス表記も修正し、空白を含む一時フォルダーへの実クローンで確認した。

更新画面の切り替えを横型タブに修正し、サイドバー用スタイルの継承を解消した。広幅・狭幅で同じ行に並ぶこと、矢印・Home・Endキーによる選択とフォーカス、対応パネルの表示を実アプリで確認した。OS・アプリ管理元と管理ツール本体の更新操作は「更新候補」へ移し、対象環境を区画内で明示する。

役割分担の追加確認で、環境・ツール一覧に残っていた候補照合・ツール導入計画・旧版整理・WinGet個別計画も「更新」に集約した。一覧の各項目から環境とツールID、WinGetパッケージIDを渡し、対象の操作区画へ移動する。別環境へ切り替えた際の選択解除と、未調査環境からの移動を含むネイティブ通し試験を通過した。

更新画面を「環境の更新／プロジェクトの更新／計画・進行状況」に分割した。環境の更新は「開発ツール／OS・アプリ／管理ツール本体」の分類で操作を切り替え、操作区画を結果より上に配置する。広幅1400px・狭幅780pxの実アプリで、主要操作が高さ900pxの最初の表示範囲に収まること、候補の対象分離、環境の引き継ぎ、タブの矢印キー操作と従来のクローン経路を確認した。長いログと配置・候補詳細は展開表示に変更した。

## 管理元別の候補取得と計画

[manager-updates.md](manager-updates.md) に対応範囲を記載した。WinGetを開発ツール候補から分離し、OS・アプリ側の候補一覧から版を指定した計画を作れるようにした。fnm・nvm-windows・pyenv・Python Install Manager・Condaの候補取得と計画を追加した。旧ランチャー・OS／アプリ同梱の案内と、取得失敗・候補なし・一覧掲載なし・導入版不明を区別する。APTは候補表示で、OSの実更新は管理元で行う。追加管理元は試験用環境で候補取得と計画作成を検証し、利用者の環境を更新してはいない。

この変更の検証ではRust単体43件・Git連携3件、TypeScriptのテスト10件、Clippy、追加管理元の試験、実アプリのWinGet候補→個別計画、配布用実行ファイルの起動を確認した。実機のWinGet export対象80件から9件の更新候補を取得できた（2026-10-24の読み取り確認）。アプリやランタイムの更新実行は行っていない。CIへtest:managersを追加したが、リモートの成功は未確認。
