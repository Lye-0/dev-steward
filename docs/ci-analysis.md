# CI/CDを含むプロジェクト解析

ローカルとGitHub上の調査は `steward-core::ci` の同じ解析処理を使用します。対応ファイルを依存・版指定ファイルとともに取得し、ファイルの内容を計画のフィンガープリントへ含めます。GitHub側は引き続き同一コミットのblobだけを取得し、クローンは不要です。

## 対象と解析の深さ

| 対象                                               | 抽出するもの                                                                                                 | 完全には評価しないもの                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| GitHub Actions `.github/workflows/*.yml` / `.yaml` | Action参照、setup系の版・版ファイル、runner、jobコンテナー、matrixとenvの単純な参照、run、作業場所、shell    | 複雑な式、matrixの実行組み合わせ、条件、再利用workflow・Action内部、サービスの実ランタイム |
| mise Action                                        | リポジトリ内のmise設定、作業場所指定、インラインのmise.toml / tool_versions、install=false                   | グローバル設定、monorepo展開、install_args、キャッシュや外部プラグインの効力               |
| Dockerfile / Dockerfile.* / *.Dockerfile           | FROM、既定ARGの単純置換、RUN、既知の公式イメージの言語系列                                                   | 実際のdigest、外部build-arg、複数行、ステージ・ARGのスコープ全体                           |
| GitLab CI、CircleCI、Azure Pipelines、Buildkite    | 対応するルート設定ファイル内のimage、既知の言語版キー、script / run / command、AzureのNode・Python導入タスク | include・extends・template・orbs・executorの展開、条件、ジョブ間順序・継承                 |
| Jenkinsfile                                        | tools内のNode・JDK・Python・Goラベルと確認事項                                                               | Groovyの実行、ラベルから実バージョンへの変換、共有ライブラリ・コマンドの完全抽出           |
| Vercel `vercel.json`、Netlify `netlify.toml`       | ファイルに明示されたbuild / install / testコマンド、既知の環境変数による言語指定                             | ダッシュボード側の設定、実デプロイの正確なパッチ版、クラウド側の修正適用状況               |

GitLabの対象名は `.gitlab-ci.yml` / `.yaml`、CircleCIは `.circleci/config.yml` / `.yaml`、Azureは `azure-pipelines*.yml` / `.yaml`、Buildkiteは `.buildkite/` 配下のYAMLです。独自名の設定や未取得の参照先を解析したとは扱いません。setup系はNode・Python・Java・Go・.NET・pnpm・Bun・uv、代表的なRust Actionを認識します。

## 判断と計画への反映

- CI/CD結果はプロジェクト詳細の専用パネルに表示し、ファイルごとに展開できます。ローカル・GitHubとも同じ表示です。
- CIのランタイムを `ci-runtime` の宣言として保存します。runnerやコンテナーも含みますが、ローカルへ導入した実体という意味ではありません。
- プロジェクトのツール・engines・packageManager等とCIの系列（Pythonはminor、それ以外はmajor）が違えば、宣言元とともに相違を表示します。matrixの意図的な別系列テストもあるため、自動では統一しません。複雑な範囲指定は単純な不一致と判定せず比較要確認にします。モノレポでは宣言元を見て対象範囲を確認してください。
- `grep`、`tee`、テストレポーター、JUnit、test-resultsを扱う手順は、テストから集計・成果物まで確認する対象に含めます。出力形式の互換性を自動的に保証するものではありません。
- 依存更新・固定版変更・検証・GitHubの静的更新方針に、CIの実行環境と確認事項を引き継ぎます。長い計画では先頭40件にまとめ、全件はプロジェクトの解析結果で確認できます。
- CIコマンドを `project.scripts` や実行ステップへ自動追加しません。既存の許可された検証コマンドの選択・実行前確認を維持します。
- CI/CDファイルやクラウド設定の自動書き換え、全製品の更新候補・脆弱性照合は提供しません。Action自体の最新版・内部ランタイムも未照合です。

## 不確実な指定と保存範囲

`22.x`、stable、latest等は実パッチ版ではありません。解決できないinputs・式・参照先やJenkinsのラベルは要確認とします。YAMLで引用符のないPythonの3.10等は桁が失われることがあるため、小数の版指定を実バージョンと確定しません。

env・secrets全体は保存しません。必要な版指定だけを取り出します。コマンドは読み取り専用の証拠として保存し、既知の認証情報を伏せ、機密情報らしいキーを含む行は非表示にします。任意の文字列に埋めた秘密情報まで完全に検出できるものではありません。

ファイルサイズ・件数の取得制限とリンクの除外は既存の調査制限に従います。1ファイルのランタイム・手順・Action参照はそれぞれ先頭200件、コマンドは2000文字までです。上限に達した場合は確認事項として表示します。

以前保存した結果は `ci` が空でも読み込めます。新しい解析を反映するには再調査してください。静的な候補と、CI実行や実デプロイで確認した結果は別の証拠です。

## 検証

- Rust単体：matrix・env・ファイル参照・Docker・各プロバイダー・未解決式・YAML小数・機密情報の抑制・miseインライン設定・指定の優先順位。
- Git連携：ローカルCI検出、系列差の表示、計画への引き継ぎ、CI変更によるフィンガープリント変化、旧データ読込。
- GitHub模擬API：クローンなしでCIと手順を取得し、静的方針へ引き継ぐ。
- Windows実アプリ：CI解析パネルを展開し、実行環境・集計手順を狭い画面でも確認する。
