# UI全体点検（2026-10-24）

## 範囲

概要、環境・ツール、プロジェクト、更新、履歴、設定を対象に、現在の実装・画面・操作を点検した。Windowsの実際のTauri/WebView2で、通常幅1400×900と最小サイズ760×600を巡回。既存の480px幅確認、分類別の表の列幅・展開、横タブのキーボード操作も維持している。

## 問題と対応

| 対象         | 問題                                                     | 対応                                                                                                       |
| ------------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 共通通知     | ダイアログ内で失敗しても、背面の通知が操作不能で読めない | ダイアログ内へ通知を表示し、エラーへフォーカス。長文は詳細を展開可能にした                                 |
| ダイアログ   | 長い情報を読むと閉じる操作が画面外へ出る                 | 見出しと閉じるボタンをダイアログ内で追従                                                                   |
| 設定         | 保存失敗でも入力を先に消していた                         | 入力を保持し、未保存と保存済みを明示                                                                       |
| 設定         | 管理対象を切り替えても入力の対応先が分かりにくい         | 環境・管理ツールごとに下書きを分離し、保存済み値を読み込む。指定一覧も対象環境に限定                       |
| プロジェクト | 詳細を読んだ後に一覧へ戻りにくい                         | 一覧への復帰ボタンとフォーカス復帰を追加                                                                   |
| プロジェクト | 検証未選択時に公開付き計画を作ろうとすると失敗する       | 作成を無効にし、検証スクリプトへ移る入口を表示                                                             |
| プロジェクト | 選択状態が計画選択や比較環境に影響される                 | 検証・依存の選択は作業対象の切り替えと再調査結果に合わせてリセット。公開選択もプロジェクト変更時にリセット |
| 取得結果     | 差分や有効ツールの結果にもPR向けの説明が出る             | 操作ごとにダイアログの見出し・説明を変更                                                                   |
| 計画         | 件数が増えると対象・進行状況を探しにくい                 | 名前・環境・コミット検索、種類・状態による絞り込み、件数表示                                               |
| 計画         | 選んだ詳細が長い一覧の下に隠れる                         | 選択時に詳細へ移動し、一覧へ戻る入口を追加。絞り込みで選択中の項目が隠れた場合も明示                       |
| 計画         | 実行操作が全工程・ログの下に埋もれる                     | 次の工程・実行場所・コマンド・確認と実行ボタンを工程一覧より先に配置                                       |
| タブ         | 詳細への自動フォーカスが矢印キー操作を奪う               | 計画を選んだときのみ詳細へ移動。タブ切り替え時はタブにフォーカスを維持                                     |
| 履歴         | 過去の失敗や対象を探しにくい                             | 文字検索、状態フィルター、件数表示、長いログの高さ制限と折り返し                                           |
| 狭い画面     | 長いパス、リポジトリ行、操作見出しが窮屈になる           | 折り返しを調整し、依存検索のラベルと入力を縦に配置。アイコンだけのナビゲーションにも名前を付与             |
| 低い画面     | 補助ナビゲーションが押し出される可能性                   | サイドバー内のスクロールと低い画面向け余白調整                                                             |

## 確認した操作と証拠

- `pnpm test`：10テスト。
- `pnpm build` と `pnpm format:check`。
- `node scripts/native-smoke.mjs`：既存の実IPC・検証用リポジトリの更新と実行に加え、`scripts/ui-review-smoke.mjs` による全6画面の巡回。
- 同名フォルダーへのクローン失敗をダイアログ内に表示。
- 独立した試験用DBだけを書き込みロックし、実際に保存失敗を発生させ、下書きが保持されDBが変更されないことを確認。
- 管理ツール切り替え時の下書き保持、計画・履歴の検索ゼロ件と復帰、状態フィルター、詳細から一覧へのフォーカス復帰。
- 画面外までページ全体が横にはみ出さないことを各画面・各サイズで確認。
- `test-results/ui-review-*-1400.png`、`ui-review-*-760.png`、`ui-review-modal-error.png`、`ui-review-settings-error.png` を生成。狭い画面の全6画面を画像でも点検。
- 配布用ビルドと `node scripts/release-smoke.mjs` による起動確認。

## 維持した設計と限界

- 広いデータ表は列の整列を保つため表の内部で横スクロールする。ページ全体の横はみ出しとは区別する。
- 更新・削除の実行前確認は維持。今回の確認で実環境のツール更新・削除やGitHubへの書き込みは行っていない。更新実行は試験用リポジトリだけ。
- 実機検証はWindows。macOS・LinuxネイティブUI、スクリーンリーダーによる読み上げ、実ユーザーによる使いやすさ試験は今回の確認に含まない。
- WSLの選択・表示と既存の対象分離は検証用データで確認。全WSLディストリビューションの実コマンドや、全管理ツール・外部インストーラーの操作を網羅した試験ではない。
- 下書き保持は設定画面内で対象を切り替える範囲。再起動をまたぐ未保存入力の復元は提供しない。
